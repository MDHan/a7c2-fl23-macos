# 安装在 writing_settings 停止：实验性专项诊断

适用报告：[Issue #1](https://github.com/MDHan/a7c2-fl23-macos/issues/1)、[Issue #2](https://github.com/MDHan/a7c2-fl23-macos/issues/2)。

## 风险与免责声明

本项目为非 Sony 官方的实验性工具。**本页新增的 `diagnose` 命令只经过离线模拟测试，尚未经过真机验证。** 以前安装脚本或本仓库 `verify` 的成功记录，不能视为这条新命令已获实机验证。

诊断设计上不写固件程序、不写或保存 AP/CP 参数、不处理 WBI，但会接管 USB、进入服务模式，并上传、执行、清理固定版本的临时 runtime 诊断模块。因此不能称为“完全只读”或“零风险”；可能发生通信中断、退出异常或其他尚未发现的问题。备份不能保证救砖，也不保证运行诊断后即可恢复菜单或正常使用。

是否运行由使用者了解以上限制后自行决定。若不愿承担额外设备操作风险，可以仅保留本地材料并在 Issue 说明暂不运行，等待进一步排查。不要为了补齐诊断反复刷写、手改状态或套用其他机身备份。目前另提供下文严格限定的实验性 WBI 收尾入口；没有通用续写、强制恢复或救砖命令。

## 运行前

1. 仅针对 ILCE-7CM2 / 原版 2.01 的本机身原始安装工作目录，状态必须为 `needs_review`，`failed_action=install`，`failed_during=writing_settings`。不要选后来为检查而新建的、不完整的 `prepare` 目录。
2. 保留所有已有目录，不覆盖或修改 `state.json`。工具会先核验原备份、候选和机身身份，任一不符即停止。
3. 如实记录报错后已经做过的关机、取电池、重启或再次运行工具等动作。不要求为运行诊断再做一次冷启动。
4. 相机当前无错误和持续异常存取，处于 MSC，实际电量至少 50%，Mac 接电。电量不足或机身异常时先在 Issue 说明现状，不要为运行命令随意拔电池或切换供电。

## 命令

在此前下载的源码仓库目录中更新工具；相机当前应没有其他工具正在操作：

```sh
git pull --ff-only origin main
./a7c2-mac check
./a7c2-mac diagnose --help
```

如更新因本地改动而失败，先保留改动，不使用强制重置。`check` 和 `--help` 不连接相机。

确认了解前述风险并决定运行后，复制下面整段。输入本次失败安装的原始工作目录完整路径（Issue #2 中是安装所用的 work2，而非后来新建的 work3），再输入相机屏幕此刻的实际电量；不要直接复用旧报告中的 52 或 75。

```sh
(
  printf '失败安装的原始工作目录完整路径：'
  read -r A7C2_DIAG_WORKSPACE
  printf '相机当前实际电量（50–100，只输入数字）：'
  read -r A7C2_DIAG_BATTERY
  sudo ./a7c2-mac diagnose --workspace "$A7C2_DIAG_WORKSPACE" --battery-percent "$A7C2_DIAG_BATTERY"
)
```

保持 USB 连接；相机再次询问连接模式时，选第 2 项「影像传输（MSC）」。不要同时运行其他相机工具。

## 查看和反馈结果

- `RESULT: diagnosed`：本轮诊断采集和正常 USB 返回完成，**不表示安装完成，也不表示所有检查均匹配**。查看摘要中的具体布尔值，等待维护者核对。
- `RESULT: diagnosed_usb_unconfirmed`：采集主体完成，但普通 USB 返回未确认。不要自动重试或依据此结果自行重启。
- `RESULT: incomplete` 或 `STOPPED`：诊断未完整结束；不推进原安装状态、不自动续写。保留输出，先说明当前机身状态。

工具在原安装工作目录下新建 `diagnostic-*` 子目录。原来的 `state.json` 不会因诊断而更新为成功；摘要也记录了 `source_state_unchanged`。每次使用新目录，不覆盖已有诊断数据。

新版诊断还在私有目录中保留原状态的逐字节副本、其哈希和本次核验的机身身份，用于把诊断证据关联到这次失败安装。这些信息不进入可分享摘要。

终端会给出 `diagnostic-summary.json` 的本地位置。**只需回复该脱敏摘要的内容**：程序是否匹配、四项目标的直接/当前/保存值及属性是否匹配、六处运行区域是否匹配、快照模式和正常 USB 是否返回。摘要不包含机身身份、原始参数、程序字节、个人路径或原始运行内存。

其余 `*.private.*`、完整读回程序、原始 runtime 二进制、原始工作目录和日志均保留本地，不上传 GitHub。截图或报错文字另行检查并去掉用户名、个人路径、身份及私人设置。诊断只提供现状证据，不会自动认可 `0x02770015` 为可放行计数器，也不会触发 WBI 收尾。


## 可选：已知停止点的实验性 WBI 收尾

针对 Issue #2 已补充的“磁盘为候选、两个菜单区域的内存仍完整匹配原版”的证据，新增 `finish-install`。**此命令尚未经过真机验证，只通过离线测试；它会实际更改 WBI 快照状态，有设备操作风险。** 不保证解决菜单缺失，也不保证各种异常下能恢复。是否尝试由使用者知情后决定；不接受风险可停止在保留现有资料的状态。

它不会重刷 AP/CP 程序或写入/保存四项目标参数，仅在以下检查全部通过后，使用固定上游的 WBI mode=0 预检查与 mode=1 收尾：

- 使用原失败安装目录，阶段、错误均精确匹配 install / writing_settings / `0x02770015`；不支持 NTSC 组合。
- 原备份与候选完整校验、原安装器40窗口二进制结果、完整读回记录和正常会话退出证据都匹配；历史证据按该次安装的时间范围匹配，缺失或不唯一即拒绝。
- 若原会话已发送服务退出请求，唯一异常精确为等待普通 MSC 身份 `0e8a` 超时，也可审查其后的完整诊断证据：按私有日志时间选择最近一次诊断，必须关联当前失败状态和同一机身，完整程序读回及原始 runtime 报告与日志一致，且正常退出并返回 MSC。后续失败、未完成或无法确定顺序的诊断会阻止此例外；不能用更早的成功摘要覆盖它们。
- 原设置快照键集合不变，四项目标在 after/stored 匹配且属性不变。除原有已允许的运行计数外，唯一额外变化必须为 chip0/0x02770015、attr=2、4字节、小端增加恰好60。
- 这是一项**仅针对此停止点的显式审查例外**，不代表已确认该字段含义或将它加入全局计数白名单。不能手改快照或状态来满足条件。
- 重新进入服务模式后，完整程序仍匹配候选；四项参数的直接/当前/保存值与属性全部匹配。六处磁盘窗口均匹配，内存仅允许已知候选，或两处菜单窗口完整匹配原版；其他内容一律拒绝。
- 当前 image_mode=2、后端为预期 wbi4，WBI mode=0 检查通过。

上述 MSC 超时例外只经过离线测试。旧版诊断缺少原状态和机身关联证据，或只有可分享摘要时，不能用于自动放行；保留原材料供核对，不手工补字段、不删除失败诊断目录。需要新的设备诊断时仍须由使用者了解风险后明确选择，不因本地审查失败自动重跑。原会话已正常返回 MSC 的既有审查路径保持不变。

先在源码仓库目录执行 `git pull --ff-only origin main`、`./a7c2-mac check`。实际电量至少50%，MSC连接，Mac接电；不要为此额外冷启动或重刷。了解风险后如决定尝试，运行整段：

```sh
(
  printf '原失败安装工作目录完整路径：'
  read -r A7C2_FINISH_WORKSPACE
  printf '相机当前实际电量（50–100，只输入数字）：'
  read -r A7C2_FINISH_BATTERY
  sudo ./a7c2-mac finish-install --workspace "$A7C2_FINISH_WORKSPACE" --battery-percent "$A7C2_FINISH_BATTERY" --accept-experimental-finish
)
```

显式参数表示你选择接受这个未实机验证的收尾和上述有限差异审查，不是自动绕过失败的通用开关。程序会先做本地审查和本次现状检查，不满足条件即停止；不需要为了通过而继续反复提供材料或试命令。

实际收尾前，原状态会另存为 `finish-*/source-state.private.json`，并写入 `finish-attempt.private.json` 防重复标记和 `finishing_snapshot` 阶段。**不得删除标记、覆盖状态或重新执行来强行重试。** 收尾、清理或退出异常会留下记录；只有 WBI 已验证完成时，才可能得到以下待冷启动状态：

- `RESULT: installed_pending_cold_start`：收尾及普通USB返回已确认。命令结束后，确认相机无错误、存取灯熄灭，拔线并正常关机，取电池约10秒再开机；检查 FL2/FL3、重设外观并拍摄回放。建议重新连接 MSC，用原目录运行 `verify --cold-start-confirmed` 完成这次异常恢复的复核。
- `RESULT: installed_pending_cold_start_usb_unconfirmed`：WBI收尾主体已验证，只有普通USB返回未确认。确认相机无错误和读写停止后，按前述步骤冷启动，不重跑收尾。
- `RESULT: incomplete` / `STOPPED`：不确认完成。保留现场和目录，不重复收尾、不手改状态，不把任意超时套用为成功。

电脑端复核命令（仅在实际冷启动后）：

```sh
sudo ./a7c2-mac verify --workspace "原失败安装工作目录完整路径" --cold-start-confirmed
```

正常完成后工具保存 `finish-*/finish-summary.json`。可选反馈此脱敏摘要和菜单/拍摄结论即可；不上传原状态副本、原始程序、参数、私有日志或二进制。即使这条路径在个别机身成功，也不代表首次安装、恢复、其他机身或 NTSC 组合已通过实测。`0x02770015` 引发的首次安装停止仍保留保护检查，尚未作为全局问题修复。
